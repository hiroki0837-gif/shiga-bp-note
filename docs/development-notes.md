## 1. これは何か

家庭血圧を患者さん自身のスマートフォンに記録し、受診時にQRコードで医療機関へ渡す仕組みです。
**サーバに患者データを置きません。** 記録は端末のブラウザ内だけにあり、外来へはQRコードで手渡します。

公開先： https://shiga-bp-note.vercel.app/

| URL | 中身 | ソース |
| --- | --- | --- |
| `/` | 患者用アプリ（医療者モードを内蔵） | `src/App.jsx` |
| `/?kiosk=1` | 患者用アプリを受付端末として起動（予備） | `src/App.jsx` の `KioskView` |
| `/terminal.html` | 受付端末（血圧・心不全の両方に対応） | `src/Terminal.jsx` |
| `/heart-failure.html` | **心不全手帳（開発中）** | `src/HeartFailure.jsx` |

心不全手帳は**まだ配布していません**。URLを知らせなければ実質非公開です。詳細は第11節。

## 2. 触る前に知っておくこと

### 2.1 URLは変えられない

記録はブラウザが**URL（オリジン）ごと**に保存します。ドメインを変えると、患者さんがそれまで入れた記録が消えます。
独自ドメインへ移す場合は、移行の仕組み（QRで書き出して新URLで読み込む等）を先に用意してください。

### 2.2 更新は受付端末が先

QRの形式を変えたら、**受付端末を先に更新**します。逆にすると、新しい患者アプリのQRを受付端末が読めません。
古い形式は読めるように残してあるので、患者さんの更新が遅れても支障はありません。

### 2.3 iPhoneはブラウザとホーム画面アプリで保存領域が別

Safariで開いたときと「ホーム画面に追加」から開いたときで、localStorageが**別々**になります（Androidは共有）。
ブラウザで初期設定・記録をしてからホーム画面版を開くと、最初からやり直しに見えます。
対策として、iPhoneのブラウザで初回設定画面を開いたときは**先にホーム画面に追加するよう案内**を出しています
（`SetupScreen` の `isIOS()` / `isStandalone()`）。患者向けマニュアルの手順も「追加→設定」の順にしてあります。
根本対策（既に入力済みのデータの移行）は「引き継ぎコード」機能が必要で、第12節の未着手項目と同件です。

### 2.4 外部ライブラリを増やさない方針

QRの生成・読み取りともに**自前実装**です（`qrMatrix` / `decodeQR`）。
地図データもアプリに埋め込んであります。通信は起動時と外部リンクを押したときだけ、という状態を保っています。
依存を増やす前に、その必要性を検討してください。現在の依存は React と recharts のみです。

## 3. QRコードの仕様

### 3.1 全体の並び

数字のみ（QRの数字モードで容量を稼ぐため）。

```
APP(1) FMT(1) build(3) idx(2) total(2) ymd(6) days(3)
  targets(6) aid(10) demo(4) learn(7) plan(4) cnt(3) records×N checksum(2)
```

- `APP` … 8＝しが血圧ノート、9＝心不全手帳。受付端末はこの1桁で振り分ける
- `FMT` … 形式番号。増やすときは `FMT_SPECS` に1行足す（既存は消さない）
- `aid` … 手帳番号（乱数10桁）。初回起動時に生成し端末に保存
- `demo` … 年齢3桁（999＝未入力）＋性別1桁
- `checksum` … 全桁の和 mod 97

### 3.2 1レコード（血圧ノート・FMT=6）

```
offset(3) 朝上(3) 朝下(3) 朝脈(3) 夜上(3) 夜下(3) 夜脈(3)
  服薬×4(4) 朝時刻(2) 夜時刻(2) 朝不整脈(1) 夜不整脈(1)  = 31桁
```

時刻は15分単位の通し番号（99＝未記録）。服薬は 0未記録／1飲めた／2飲み忘れた。

### 3.3 入れていないもの

**氏名・生年月日・カルテ番号・メモの内容・月1回の体重**はQRに入れていません。
メモを入れない理由は、容量（日本語は数字の数倍）と、氏名や病名が書かれ得るためです。

### 3.4 分割

1枚あたり40件で分割。前2週・1か月＝1枚、2か月＝2枚、3か月＝3枚。
3か月を1枚に詰めると129マス角になり、カメラでの読み取りが不安定になるため分割しています。

## 4. QRの読み取り（自前実装）

`decodeQR(gray, w, h)` が入口。二値化 → 位置検出パターン探索 → 射影変換 → 格子読み取り → リード・ソロモン訂正。

**なぜ自前か**：ブラウザ標準の `BarcodeDetector` は Safari が未対応で、iPad で使えないためです。
Chrome では標準機能を先に試し、失敗したときに自前処理へ回します。

**実装で詰まった点**（同じ轍を踏まないように）：

- 位置検出パターンの走査は、行のランレングスから 1:1:3:1:1 を探す。状態機械で書くと最初の明色区間を数え違える
- 弧の切り出しは**接合点を両端に含める**。含めないと隣り合う図形で別の線になる
- Forney の式に `X_k` の係数が要る。抜けると誤り訂正が「たまに成功する」挙動になる
- 1マスが4画素未満のときは3×3の平均を取ると隣のマスを拾う。1画素だけ見る
- 位置検出パターンの中心は重心で精密化する。整数のままだと小さいQRで格子がずれる

**検証結果**：傾き45度まで、ぼけ、ノイズ、明るさムラ、1マス3画素まで安定。強い遠近（正面から30度超）は弱い。
条件を混ぜた60回で成功率93%、1枚あたり約90ms。カメラは毎秒8回読むので実用上は問題なし。

## 5. データの保存と暗号化

`window.storage`（プレビュー環境）または `localStorage`（本番）に保存。冒頭のシムで吸収しています。

**暗証番号を設定すると暗号化されます。** PBKDF2（15万回, SHA-256）で鍵を作り、AES-GCM で全体を暗号化。
封筒の形は `{ enc:1, kdfSalt, iv, payload, security }` で、ロック画面を出すために `security` だけ平文です。

**生体認証を使うと弱くなります。** 暗証番号なしで開くには鍵を端末内に置く必要があるためです。
設定画面にその旨を明記しています。この妥協を消すなら、生体認証をやめるしかありません。

**暗証番号を忘れると復元できません。** 暗号化した以上どうにもならない部分で、警告を厚くしてあります。

## 6. 判定の方針

**アプリは診断しません。** 受診の目安を伝えるだけです。

- 判定する … 目標との比較、記録の続き具合、服薬の達成率、著しく高い日
- 判定しない … **不整脈マークの回数**（表示のみ）、診断、薬の増減

不整脈マークの判定を入れないのは、機種によってマークの出やすさが違い、閾値に根拠を置けないためです。
一度実装しましたが、方針として削除しました。回数を見て判断するのは医療者側、という整理です。

- 診断基準は据え置き（診察室140/90以上、家庭135/85以上）

## 8. 印刷まわり（つまずいた点）

紙に出すときの不具合は、原因が分かりにくいものが多かったので記録します。

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| 読み取り欄とカメラが印字される | 印刷対象から外していなかった | `no-print` を付与。`video, canvas` も常時非表示 |
| 表が右端で切れる | 横スクロールの枠の外は出ない | 印刷時 `overflow: visible`、`min-width: 0` |
| ほぼ空白のページが増える | グラフが画面幅のまま紙からはみ出し、横方向にページが増えていた | `overflow-x: hidden`、recharts の幅を100%に |
| カード全体が次ページに送られ大きな余白 | `section` に `break-inside: avoid` を掛けていた | グラフ1つ・表1つの単位だけに限定 |
| 列幅が週ごとにばらつく | 中身に応じた自動幅 | `table-layout: fixed` ＋ `colgroup` で割合指定 |
| カーソルの吹き出しが残る | recharts のツールチップ | `.recharts-tooltip-wrapper` を非表示 |
| 週平均の列で「138/70」が「138/7」に切れる | `table-layout: fixed` の列幅（9%）が太字の値より狭く、セルの `overflow: hidden` で刈られていた。印刷CSSの `table { font-size: 9.5px }` は**th/tdのインライン指定に負けて無効**だった | 週平均の列を12%に拡大。縮めたいときは `th, td { font-size: … !important }` と**セル自身に**指定する |
| グラフが改ページで泣き別れ、次ページの表に重なる | flex／gridの中では `break-inside: avoid` を無視するブラウザがあり、固定高さのグラフ枠が分断されるとSVGが後続の上に描かれる | 印刷時は縦積みの `.flex-col` と `.chart-grid` を `display: block` に戻す（gapの代わりに `> * + *` にmargin） |
| グラフが紙面中央に小さく寄る／枠からはみ出して重なる | rechartsのSVGはviewBox付きなので、幅だけ100%にするとletterboxで中央に縮む。幅100%＋高さautoにしても、ResponsiveContainerがインラインで入れる `max-height` が残っているとSVGだけ拡大されて枠からあふれる | `.recharts-wrapper` とSVGに `width:100%; height:auto;` **`max-height:none`** をセットで。viewBoxのおかげで紙幅に相似拡大される |
| 受付端末（予備・`?kiosk=1`）の印刷にグラフが出ない | 印刷用ブロックを `display: none` にしていたため、グラフが0サイズで測られていた | 画面外（`position:absolute; left:-99999px` に実寸幅で）描いておき、印刷時に通常配置へ戻す |
| 凡例の「朝／夜」が線の下に折り返し、伸びた線が日付ラベルに重なる | `.recharts-wrapper svg { width:100% }` が**凡例の線アイコンのSVGまで**引き伸ばしていた | グラフ本体だけ `.recharts-wrapper > svg`（直下）に限定。`.recharts-legend-wrapper svg` は属性幅(18px)のまま |
| グラフと凡例が離れすぎる | rechartsのLegendはSVG下部に**画面で測った凡例の高さぶんの余白**を確保する。印刷でSVGを拡大するとその余白も拡大されるが、HTMLの凡例は等倍のまま最下部に残るため隙間が倍率に比例して開く | rechartsのLegendをやめ、**グラフ枠のすぐ下に自前のHTML凡例**（`legend()`、色付きの「━ 上 ━ 下」）を置く。SVGの外のHTMLなので倍率の影響を受けない |
| 脈拍のグラフだけ印刷で小さい | 画面で血圧2つはグリッドの半分幅、脈拍は全幅で測られ、紙に合わせる拡大率がグラフごとに変わる | 3つとも同じグリッド（`chart-grid`）に入れて同じ幅で測らせる |
| 書き出し表の見出し（朝不整脈マーク等）が隣の列に重なる | 均等割り（`table-layout: fixed`）の列に `nowrap` の長い見出しがはみ出す | 紙では `th { white-space: normal !important }` で折り返しを許す |
| 服薬4枠のとき「お薬 朝/昼/夕/寝る前」が隣のチェック印に重なる（画面） | 行見出しが `nowrap` のままセル幅を超えてはみ出す | 複数枠のときは「お薬」＋2行目に小さく枠名を表示。チェック印のセルも折り返し可に |

ページ下部のURLと日付は**ブラウザが付けるもの**で、CSSでは消せません。印刷画面で「ヘッダーとフッター」を外します。

印刷の検証は、画面の幅（スマホ幅〜デスクトップ）と印刷倍率（100%・125%）を変えた組み合わせで行うこと。
不具合の多くは「画面で測ったサイズのまま紙に出る」ことが原因で、狭い画面や倍率変更のときだけ現れます。

## 10. 受付端末

設定は暗証番号の内側。画面すみの小さな歯車から入ります。

- 読み取る方法（カメラ／読み取り機）… 読み取り機を選ぶとカメラを起動しない
- 紙を受け取る人（患者さん／医療者側）＋読み取ったあとの案内 … 完了画面の文言が変わる
- 印刷のタイミング、用紙、向き、文字の大きさ、テスト印刷
- CSV出力と保存先フォルダ（Chrome/Edgeのみ。iPad Safari は非対応）
- 直近5件の再印刷（**メモリ上のみ**。閉じると消える）

**プリンタはブラウザから選べません。** 端末の「通常使うプリンター」で決まります。
ダイアログを出さないには Chrome を `--kiosk-printing` で起動します。

CSVは `受診記録_累積.csv` に1日1行ずつ追記。受診のたびに期間が重なるため**同じ日の行が複数入ります**。
解析時は手帳番号と日付でまとめ、読取日時の新しい行を採用してください。

## 11. 心不全手帳の状況

血圧ノートの姉妹アプリです。`/heart-failure.html` でビルド対象に入れてありますが、**まだ配布していません**。
大幅な改訂が予定されているため、いまは触らずに置いてあります。

### 反映済み

服薬の4枠選択（朝・昼・夕・寝る前）、その他タブの分割、初回設定（生年月日・性別・身長、和暦表示）、
匿名の手帳番号、QRへの年齢・性別・手帳番号の追加、アプリ種別の1桁（APP=9）、BMI表示、
サマリーを期間カードの中へ、SHDの配色、施設マップ、設定の保存・破棄、受付端末との連携。

### 未反映（血圧ノートにはあるが、こちらにはないもの）

- **メモ欄**（選択肢＋自由記載）。QRには載せない方針も含めて未実装
- **保存データの暗号化**（PBKDF2＋AES-GCM）。いまは平文で保存
- **印刷まわりの修正**。第8節の表にある不具合が**そのまま残っています**。印刷を使う前に必ず反映すること

### 受付端末との関係

受付端末は**すでに心不全手帳のQRを読めます**（FMT 1〜7に対応、体重グラフと症状の行を含む印刷様式も用意済み）。
心不全手帳を公開すれば、そのままつながります。

### 改訂するときの注意

記録項目を増やす場合は、`FMT_SPECS` に新しい番号を足し、**受付端末（`src/Terminal.jsx` の `APPS["9"].specs`）にも同じ行を足します**。
記録の構造そのもの（1日1レコードという前提）を変える場合は、読み取り処理の書き直しが必要です。
