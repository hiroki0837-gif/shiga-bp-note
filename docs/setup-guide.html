しが血圧ノート　導入の手引き

施設に導入する方へ　／　滋賀医科大学医学部附属病院 循環器内科

1. 全体像

患者さんのスマートフォンで血圧を記録し、受診時にQRコードで医療機関に渡す仕組みです。サーバに患者データを置かないため、個人情報の管理が単純になります。

患者用アプリ患者さんのスマートフォンで開く。記録はその端末の中だけに保存
医療者モード診察室でQRを読み、その場でグラフや平均を見る
受付端末患者さんが自分でQRをかざし、自動で印刷（任意）

アプリのインストールは不要です。QRコードを読み取ってブラウザで開くだけで使えます。

2. 導入の段階

いきなり全部そろえる必要はありません。次の順で進めると、無駄な投資になりません。

第1段階公開して、数名の患者さんに試してもらう実質0円
第2段階診察室で医療者モードを使う既存のiPad・PCで可
第3段階受付端末を設置する7〜19万円
第4段階CSVを貯めて研究に使う倫理審査が必要

4. 準備するもの

  • GitHubのアカウント（無料）
  • Vercelのアカウント（無料。GitHubでログインできます）
  • 公開するURLの決定（あとから変えられません）
  • 導入施設として載せる情報（名称・診療科・住所・院長名・ホームページ）

URLは一度決めたら変えないでください。記録はブラウザがURLごとに保存します。URLを変えると、患者さんがそれまで入れた記録が見えなくなります。

公開する手順

GitHub と Vercel を使います。無料です

5. 手元で動かして確認する

  1. Node.js（18以上）を入れます
  2. プロジェクトのフォルダで npm install を実行します
  3. npm run dev を実行し、表示されたアドレス（http://localhost:5173）を開きます
  4. 記録を入れる、QRを出す、医療者モードで読む、まで一通り触ります

6. GitHub に置く

  1. GitHubで新しいリポジトリを作ります（Private で構いません）
  2. プロジェクトのフォルダをそこに push します

node_modules と dist は .gitignore で除外済みです。そのまま push してください。

7. Vercel に公開する

  1. Vercelにログインし、New Project を押します
  2. 先ほどのリポジトリを選びます
  3. 設定はそのままで Deploy を押します（vercel.json の内容が使われます）
  4. 数分で公開されます。表示されたURLを控えます

以後は、GitHubに push するたびに自動で反映されます。URLは変わりません。

8. 実機で確かめる

公開したら、必ず実際の端末で次を確認してください。ここは机上では分かりません。

  • スマートフォンでQRを読み、アプリが開く
  • ホーム画面に追加できる
  • 記録を入れて、閉じて開き直しても残っている
  • 暗証番号を設定し、開き直して解錠できる
  • Face ID・指紋が登録できる（対応端末のみ）
  • 受診用QRが出て、医療者モードのカメラで読める
  • 印刷したときに表が途中で切れていない

カメラでの読み取りは、画面の明るさを上げ、まっすぐ向けると成功しやすくなります。斜めから見ると読めないことがあります。

9. 掲示物を作る

  1. docs/poster-qr.html をブラウザで開きます
  2. 上の欄に、公開したURLを入れてQRコードを作り直すを押します
  3. 印刷 / PDFで保存で2枚出ます（1枚目が掲示、2枚目がリーフレット）
  4. 実際に印刷したものを、スマートフォンで読み取れるか確かめます

受付端末の設置と運用開始

10. 受付端末を置く

  1. 端末で https://shiga-bp-note.vercel.app/terminal.html を開き、ブックマークします
  2. ブラウザを全画面にします
  3. 設定（画面すみの歯車）を開き、まず暗証番号を決めます
  4. 読み取る方法（カメラ／読み取り機）、印刷、CSV、端末名を設定します
  5. テスト印刷で紙の出かたを確かめます

プリンタはブラウザから選べません。出したいプリンタを、端末の「通常使うプリンター」に設定してください。

印刷画面を出さずに刷るには、Chromeを --kiosk-printing を付けて起動します。デスクトップのショートカットに書いておくと便利です。

11. 職員への説明

  • docs/manual-staff.html を印刷して配る
  • 受付での声かけを決める（例：「お持ちのスマホでQRを出してかざしてください」）
  • 読めなかったときの対応を決める（紙の手帳で受ける、など）
  • 印刷に失敗したときの再印刷の場所（設定 → 直近の読み取り）を共有する

12. 患者さんへの案内

  • docs/manual-patient.html を印刷して配る
  • リーフレットを外来に置く
  • 掲示物を受付や血圧計の横に貼る
  • 最初の数名は、その場で一緒に設定まで済ませる

最初の患者さんは、アプリに慣れている方を選ぶとつまずきが少なくなります。うまくいった例を職員が見ておくと、次から案内しやすくなります。

13. 始めたあとに見ること

1週間後実際に使えているか、記録が続いているかを数名に聞く
1か月後受付での所要時間、読み取り失敗の頻度を確認する
3か月後続けている割合、外来での使われ方を振り返る

14. 更新するとき

  1. ソースを直して GitHub に push します（自動で反映されます）
  2. QRの形式を変えたときは、受付端末を先に更新します
  3. 患者さんの端末は、アプリを閉じて開き直すと新しくなります

15. 研究に使う場合

CSVを貯め始める前に、倫理審査の方針を決めてください。あとから決めると、集めたデータが使えなくなることがあります。

  • 研究計画書と倫理審査の申請
  • 手帳番号とカルテ番号の対応表を、誰がどこで管理するか決める
  • CSVの保存場所と、廃棄の方法を決める
  • 患者さんへの説明（オプトアウトで足りるか、同意が要るか）

アプリの有償提供を考える場合は、大学の産学連携部門にも相談してください。職務として作ったものの権利と、利益相反の整理が必要になります。

16. 困ったとき

患者さんの記録が消えたブラウザの履歴やサイトデータを消すと記録も消えます。復元はできません
QRが読めない画面を明るくし、まっすぐ向けてもらいます。それでも読めなければ画面を直接見せてもらいます
印刷されない設定 → 直近の読み取り から、最新5件を出し直せます
暗証番号を忘れた記録は復元できません。すべて消して最初からになります
